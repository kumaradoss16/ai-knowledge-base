# Prompt: Turn a Project into a Product Requirements Document (PRD)

## Instruction

Based on the project described above *(or: the project described below)*, create a complete, overall **Product Requirements Document (PRD)**.

## Project Details

> Fill this in only if the project has not already been discussed in this chat.

- **Project description:** [Short description of the project]
- **Goal:** [What the project aims to achieve]
- **Known constraints:** [Budget, timeline, tech, compliance, etc.]

## Required Structure

Structure the PRD with the following sections:

1. **Document Overview**: title, version, date, author, status
2. **Executive Summary**: what the product is and why it matters, in 3-5 sentences
3. **Problem Statement**: the pain points and the opportunity
4. **Goals & Success Metrics**: measurable objectives and KPIs
5. **Non-Goals**: what is explicitly out of scope
6. **Target Users & Personas**: key user types, their needs and behaviors
7. **User Stories & Use Cases**: in the format *"As a [user], I want [action], so that [benefit]"*
8. **Functional Requirements**: numbered and prioritized (Must-have / Should-have / Nice-to-have)
9. **Non-Functional Requirements**: performance, security, scalability, accessibility, compliance
10. **User Flow & Experience**: key journeys, screens, or interactions
11. **Technical Considerations**: architecture, tech stack, integrations, data requirements, dependencies
12. **Assumptions, Risks & Mitigations**
13. **Release Plan & Milestones**: phases (MVP, v1, v2), timeline, and deliverables
14. **Open Questions**: items that need decisions or clarification
15. **Appendix**: glossary, references, competitor notes

## Guidelines

- Be specific and actionable. Avoid vague statements.
- Use tables for requirements, metrics, and milestones where helpful.
- Give each requirement a unique ID (e.g., `FR-01`, `NFR-01`) and a priority.
- If any information is missing, state your assumption clearly rather than leaving the section blank.
- Write for both engineers and non-technical stakeholders.
- Keep a professional, concise tone.
